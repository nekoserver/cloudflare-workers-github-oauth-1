Cloudflare Workers GitHub OAuth

新規インスタンス構築手順

前提条件
  • GitHub アカウントにログイン済み
  • Cloudflare アカウントにログイン済み
  • wrangler CLI インストール済み・wrangler login 済み
  • npm が使用可能
  • Claude Code（Web版 or CLI版）が使用可能

変数表

作業開始時にすべて決定し記入する。以降は各フェーズからこの表を参照する。

変数説明値
{N}連番
{OWNER}GitHub ユーザー名 / Org 名
{CF_SUBDOMAIN}CF Workers サブドメイン（※）
{CLIENT_ID}OAuth App Client ID
{CLIENT_SECRET}OAuth App Client Secret
{JWT_SECRET}JWT 署名用シークレット

※ Cloudflare Dashboard > Workers & Pages > Overview 右側に表示されている。

A. リポジトリの作成とクローン

A-1. 連番の決定

GitHub 上の自分のリポジトリ一覧で cloudflare-workers-github-oauth-* を確認し、次の番号を決定する。 → 変数表の {N} に記入。

A-2. GitHub でリポジトリを新規作成

  • 名前: cloudflare-workers-github-oauth-{N}
  • プライベートリポジトリ
  • README / .gitignore の自動生成はしない

A-3. テンプレートのクローンとリモート付替え

git clone https://github.com/{OWNER}/cloudflare-workers-github-oauth.git \
  cloudflare-workers-github-oauth-{N}

cd cloudflare-workers-github-oauth-{N}

git remote set-url origin \
  https://github.com/{OWNER}/cloudflare-workers-github-oauth-{N}.git

git push -u origin main
  • git remote -v で origin が新リポジトリを指している

B. GitHub OAuth App の作成

B-1. OAuth App を新規登録

GitHub > Settings > Developer settings > OAuth Apps > New OAuth App

項目値
Application namecloudflare-workers-github-oauth-{N}
Homepage URLhttps://cloudflare-workers-github-oauth-{N}.{CF_SUBDOMAIN}.workers.dev
Authorization callback URLhttps://cloudflare-workers-github-oauth-{N}.{CF_SUBDOMAIN}.workers.dev/github/callback

B-2. Client ID / Client Secret を取得

  1. 登録直後の画面で Client ID をコピー → 変数表に記入
  2. "Generate a new client secret" → Client Secret をコピー → 変数表に記入
注意: Client Secret はこの画面でしか表示されない。必ずこの時点で記録すること。
  • Client ID が Ov23li で始まる文字列である
  • Client Secret が 40 文字の 16 進数文字列である

C. プロジェクト設定の書き換え

C-1. wrangler.toml の name を更新

name = "cloudflare-workers-github-oauth-{N}"

検証: grep '^name' wrangler.toml

重要: name を間違えるとデプロイ先が別 Worker になり redirect_uri mismatch が発生する。 → T-1

C-2. wrangler.toml の GITHUB_CLIENT_ID を更新

廃止: [vars] には書かない。E. シークレット設定で wrangler secret put に一元化。 理由は T-5 を参照。

C-3. コールバック URL パスの確認

ソースコード側のパスが /github/callback であることを確認（通常変更不要）:

// src/index.ts
const redirectUri = `${url.protocol}//${url.host}/github/callback`;
確認箇所期待されるパス
GitHub OAuth App 設定画面.../github/callback
src/index.ts（/auth/github ルート内）/github/callback
src/index.ts（/github/callback ルート内）/github/callback
  • wrangler.toml の name がインスタンス名と一致
  • [vars] に GITHUB_CLIENT_ID が存在しない
  • コールバック URL パスが GitHub 側とコード側で一致

D. 依存関係のインストールとデプロイ

D-1. npm install

npm install

D-2. Cloudflare Workers へデプロイ

npm run deploy

デプロイ先: https://cloudflare-workers-github-oauth-{N}.{CF_SUBDOMAIN}.workers.dev

D-3. 疎通確認

curl https://cloudflare-workers-github-oauth-{N}.{CF_SUBDOMAIN}.workers.dev/health
  • node_modules/ が作成されエラーなし
  • デプロイ成功、Worker URL が正しい
  • /health が {"status":"ok"} を返す

E. Cloudflare シークレットの設定

E-1〜3. シークレットの設定

3 つのシークレットをすべて wrangler secret put で設定する。 値は変数表を参照。

# E-1: Client ID
npx wrangler secret put GITHUB_CLIENT_ID

# E-2: Client Secret
npx wrangler secret put GITHUB_CLIENT_SECRET

# E-3: JWT Secret
npx wrangler secret put JWT_SECRET
絶対に wrangler.toml の [vars] に書かないこと。 → T-5. vars と secret の競合

E-4. シークレット設定後の再デプロイ（必要に応じて）

npm run deploy
  • 3 つの secret すべてで "Success" が表示された

F. Claude Code へのリポジトリ許可設定

F-1. リポジトリ権限の付与

Claude Code（Web版）設定にて {OWNER}/cloudflare-workers-github-oauth-{N} に読み取り・書き込み・コミット&プッシュを許可。

F-2. Cloudflare MCP の確認（任意）

Claude Code から Cloudflare 操作を行う場合は MCP 接続を確認。

  • Claude Code からリポジトリにアクセスできる

G. OAuth フローの動作確認

G-1. ログインページの表示

ブラウザで https://cloudflare-workers-github-oauth-{N}.{CF_SUBDOMAIN}.workers.dev/ にアクセス。

G-2. OAuth フローの通し確認

  1. 「GitHub でログイン」をクリック
  2. GitHub 認証画面が表示される
  3. "Authorize" をクリック
  4. /welcome にリダイレクトされる
  5. ユーザー名・メールアドレスが表示される

エラーが出た場合 → T. トラブルシュート

  • ログインページが表示される
  • OAuth フローが最後まで正常に完了する

T. トラブルシュート

T-1. redirect_uri mismatch

GitHub 側で「redirect_uri mismatch」が表示される。

原因確認方法対処
wrangler.toml の name が別 Worker を指している grep '^name' wrangler.toml C-1 で修正して再デプロイ
コールバック URL パスの不一致 OAuth App 設定画面とソースコードを比較 C-3 で統一

T-2. "GitHub OAuth is not configured"

GITHUB_CLIENT_ID が未設定。→ E. シークレット設定を実行。

T-3. "Authentication failed"

GITHUB_CLIENT_SECRET が間違っている。→ E-2 を再実行。

T-4. "Invalid state parameter"

CSRF state の不一致。ブラウザの Cookie をクリアして再試行。

T-5. vars と secret の競合

wrangler.toml の [vars] に GITHUB_CLIENT_ID を書くと、 wrangler secret put の値と競合し [vars] 側が優先されてしまう。

  • [vars] から GITHUB_CLIENT_ID の行を削除する
  • シークレットは wrangler secret put に一元化する
  • 再デプロイして反映

T-6. "JWT_SECRET is not configured"

JWT_SECRET が未設定。→ E-3 を実行。
