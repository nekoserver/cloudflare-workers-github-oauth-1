SaaS integration map

PR要約パイプラインが各SaaSに持たせている役割

POST /webhook/github を起点に、GitHub・Cloudflare Workers AI・Cloudflare D1・Slack の4つに 役割を分担させている。「何をやらせたか」と「今も維持している役割」を1枚の図にまとめた。

各SaaSの役割と現状

GitHub

PRの作成・更新(opened / synchronize)をWebhookで通知させる「発火源」。HMAC署名でなりすましを防ぐ窓口も兼ねる。

現状: 維持 — /webhook/github 1本で全リポジトリのイベントを受け続けている

Cloudflare Workers AI

diffとPR本文を渡すと日本語要約を返す「生成エンジン」。[AI]バインディングでWorkerに直結し、外部APIキー管理が不要。

現状: 維持 — モデル名はAI_MODELで上書き可能、未設定時はデフォルトにフォールバック

Cloudflare D1

要約結果・失敗理由・自動診断・人手フィードバックをすべて記録する「台帳」。cf-authの/wspaceが読み取り専用で参照する共有DBでもある。

現状: 維持 — ai_summary_log / ai_summary_reviews の2テーブルに一本化

Slack

要約をBlock Kitで通知し、「詳細を見る」ボタンからモーダルでD1の全情報を見せる「表示面」。外部URL遷移を経由しないループを持つ。

現状: 維持 — POST /slack/interactions が署名検証してモーダルを都度組み立てる

役割が固まるまでの主な変化

SaaSやったこと今の役割への効き目
GitHub App Webhook基盤を先に構築し、後からpull_request分岐を同じ窓口に追加 「イベント種別が増えても受信口は1つ」という設計が今も踏襲されている
Workers AI diffが空だと要約自体がスキップされNULLになる不具合を修正 diff取得に失敗してもタイトル・本文からのフォールバック生成が今の標準動作
Cloudflare D1 ログテーブルを2段階で拡張(基本ログ→resolved/tags/reviews) 失敗時の自動診断(auto-diagnosis)が常時記録される状態を維持
Slack plain textからBlock Kit化し、外部URL遷移をモーダルに置き換え Slackを離れずに要約全文を確認できる体験が定着
